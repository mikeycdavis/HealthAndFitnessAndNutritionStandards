## What

A human decides whether the four dispositions warrant recording four attestations, and if so the
release mechanics follow: verify against the real repository, remove CI's exit-4 allowance, move
`VERSION` off `1.0.0-dev`, re-run the gate, tag `v1.0.0`.

## Why

An attestation carries a `reviewedBy` identity. Only a person can supply one.

## Notes

**Blocked on:** a human reviewer. Not on any repository work — there is none outstanding.

The repository reports `NOT_EVALUATED` at exit 4, and that is correct rather than a failure state.
Nothing has failed; nothing has been established either.

**It reported `COMPLIANT` once, at `ad6bdcb`, and the attestations were withdrawn.** The transition
passed every structural test below — exactly four rules attested, invariant `screened`,
`health.evidence-quality-noted` untouched, all guards and 160 tests green — and was still invalid,
because the `reviewedBy` identity came from a drafted decision rather than from the person named. The
structural test is necessary and is not sufficient.

An attestation dry run in a scratch copy of `0acc6cc` verified the release condition structurally:
with four attestations added and nothing else changed, `check` reported `COMPLIANT` at exit 0, the
integrity invariant reported `screened`, and `health.evidence-quality-noted` stayed
`not-evaluated` — applicable, but a recommendation, so non-blocking. The scratch copy was deleted
and this repository's policy was never touched.

The test that matters is not that exit 4 becomes exit 0. It is that it does so **for exactly those
four new pieces of human evidence, with Standard 42 still `screened`, all mechanical gates still
green, and nothing else having moved to obtain `COMPLIANT`.**
