## What

Development and release execute the identical evaluation: same command, same policy, same rule
states, same exit codes. Only the external gate's accepted result set differs.

## Why

`NOT_EVALUATED` may be tolerated during ordinary development and must not be tolerated at a release
gate. That is a property of the gate, not of the evaluator.

## Notes

**No `check-dev` versus `check-release` semantic fork.** Two commands drift; one command with two
acceptance sets cannot.

Same reasoning as `plan()` and `apply()` sharing one code path here, which is what makes a dry run
structurally unable to diverge from the apply it predicts. Requirement 5 of EP-03.
