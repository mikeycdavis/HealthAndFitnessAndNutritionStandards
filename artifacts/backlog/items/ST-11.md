## What

Run the CI job as a matrix across the Node versions `package.json` declares support for — currently
18, 20, 22, and 24 — instead of the single pinned 20. Bump `actions/checkout` and `actions/setup-node`
to v5 with it.

## Why

`engines` says `>=18`. CI exercises one version. Everything between the two is asserted rather than
demonstrated.

That gap is not theoretical here. It hid a defect for the entire life of the repository: `npm test`
was `node --test "test/*.test.mjs"`, and glob expansion inside `--test` only arrived in Node 21. On
the maintainer's Node 24 the suite ran; on every Node in the declared range it found nothing and
exited 1. The suite had never executed in CI at all, and thirteen consecutive billing failures meant
nothing ever contradicted that. Found by the first genuinely executed run, on the release candidate.

`test/guards.test.mjs` now asserts that no glob appears in the test command and that every test file
on disk is named in it, which closes that specific hole. A matrix closes the class.

## Notes

**Deferred, not dropped, and deliberately not part of IN-02.** The adoption and enforcement work is
the higher-leverage next problem; this is hardening that should not interrupt it.

`actions/checkout@v4` and `actions/setup-node@v4` currently emit a Node 20 deprecation warning on
every run. It is informational — the warning is about the actions' own runtime, not the
`node-version` the steps run under — and rides along with this item unless GitHub attaches a
deadline to it, in which case it becomes urgent on its own.

Changing the matrix changes nothing an adopter is evaluated on: no standard, rule, policy semantic,
or evaluator behaviour is involved.

## Reopened 2026-08-27

The stated deferral reason had discharged. It read *"the adoption and enforcement work is the higher-leverage
next problem; this is hardening that should not interrupt it"* — and that work now sits in StandardsEnforcer,
with every remaining EP-03 child `DEFERRED`. Nothing was left to interrupt.

FE-17, EP-04 and IN-03 moved to `IN_PROGRESS` with this item, for the mechanical reason recorded on IN-02
on 2026-08-25: `backlog-reconcile` treats `DEFERRED` as a closed state, so a deferred ancestor over live
work invites a proposal to close the branch.

**The matrix is 18, 20, 22, 24 and 26, not the four this item named when it was written.** "Currently 18,
20, 22, and 24" was a snapshot taken on 2026-08-12. Node 26 exists and `>=18` covers it, so omitting it
would have rebuilt the exact gap this item closes — a declared-supported version no run ever exercises.
Its existence was established by asking the registry (`docker manifest inspect node:26-bookworm`), not
recalled: the point of the item is that the supported range is not something to assert from memory.

**The guard's first draft passed a mutation it should have failed.** It matched the workflow as a whole,
and `.github/workflows/ci.yml` opens with a long comment explaining why the checkout is not shallow — so
changing the real step to `fetch-depth: 1` left the assertion green on the strength of the prose above it.
Use is not mention. Every assertion now reads the `jobs:` section with comment lines stripped, and the
shallow-checkout mutation fails as it should.

Nine mutations were run against the guard and all nine were caught: drop a middle major, drop the floor,
pin a literal version, re-enable `fail-fast`, downgrade an action to v4, shallow the checkout, re-enumerate
a pipeline stage in the job, add a second copied job, and shrink the matrix to one version.
