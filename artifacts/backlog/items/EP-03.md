## What

Eight requirements covering organisation-level discovery, self-protecting enforcement, umbrella
composition, release migration classification, one evaluation path, version pinning, bootstrap, and
test prioritisation.

## Why

It is the first post-1.0 work, ahead of adding more health rules. More rules deepen a pack nobody
is required to consult.

## Notes

**No longer dormant.** `v1.0.0` was certified and tagged at `570c45b` on 2026-08-12, which was the
condition on starting this epic. `7f59f8b` remains the baseline against which any future
certification diff must first be explained; it does not advance for release.

**Agreed order, decided 2026-08-12 and recorded here rather than left in conversation:**

```
FE-13 -> FE-14 -> FE-09 -> FE-08 -> FE-12 -> FE-15 -> FE-11 -> FE-10
```

The reasoning, which matters more than the sequence: get the basic adoption contract in place first
— pin the immutable release, bootstrap adoption, make enforcement hard to disable — then add
organisation-level discovery, because discovering non-adopters is only useful once adopting is
possible and enforcement is not trivially switched off. Harden dev/release consistency and
actionable-surface testing next. Migration semantics and cross-pack composition come last: FE-10
carries the largest remaining normative design surface, and deciding it early would freeze a
cross-domain precedence ordering that nothing currently justifies.

FE-13 is unblocked by the existence of the `v1.0.0` tag and is the natural first item.

**The problem has changed shape.** Through 1.0.0 the question was whether these standards are sound.
It is now whether every applicable project actually uses them, and whether bypass is harder than
compliance.

The full text of all eight requirements lives in [BACKLOG.md](../../../BACKLOG.md) and is not
duplicated into the features below — those track liveness, BACKLOG.md holds the reasoning. The one
deliberate omission there is a complete cross-domain precedence ordering, which is left unfrozen on
purpose: only the dominance of `BLOCKED_BY_INVARIANT` is justified by what is currently known, and
writing the rest into a backlog entry would be making exactly the cross-domain normative decision
the requirement warns against.
