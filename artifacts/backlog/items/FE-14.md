## What

An `init` that installs the policy structure, agent instructions, CI workflow, evidence and
attestation locations, and the version pin; identifies applicable standards; identifies
prohibitions **before** implementation; produces an honest initial `NOT_EVALUATED`; and states
exactly what evidence or review is missing. Running it again reconciles rather than overwrites.

## Why

A bootstrap that produced a green result would be lying on day one. The honest initial state of an
adopting project is that nothing has been established.

## Notes

It must not convert heuristic detection into an applicability judgement — see FE-08.

**Generated agent instructions are part of this feature, deliberately not a ninth requirement.**
`init` should *generate* the adopting repository's agent instructions rather than expecting a human
to paste them correctly. Substance to be specified during design: determine applicability, run the
check, identify prohibitions before implementing, refuse to implement anything violating a
prohibition or invariant, never weaken or reclassify a standard to permit a desired implementation,
preserve `NOT_EVALUATED` rather than manufacture compliance, re-run the check afterwards, and never
claim compliance merely because automated checks passed.

The workflow that produces is `applicability → prohibition scan → plan → code → check → evidence`,
rather than `code → maybe remember the standards later`. That difference is the point of the whole
epic.

Requirement 7 of EP-03.
