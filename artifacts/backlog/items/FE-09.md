## What

The standards status check required through branch protection, Code Owner review actually enabled
rather than merely documented, and `CODEOWNERS` owning itself alongside the policy and workflow
surfaces.

## Why

`CODEOWNERS` without "Require review from Code Owners" enabled documents an expectation and blocks
nothing. And if `CODEOWNERS` does not own itself, the first line of any bypass is deleting the line
that would have caught it.

## Notes

Prefer GitHub's missing-required-check behaviour to bespoke logic for detecting deletion of the
enforcement workflow: a required check that never reports leaves the pull request permanently
pending, which blocks by construction rather than by a diff-inspecting rule that could itself be
wrong.

The highest-risk change in an adopting repo is not a softened sentence of guidance. It is a
one-line applicability flip — which is an argument for the policy schema staying owned here, since
an adopter's CI then inherits `BLOCKED_BY_INVARIANT` on an `applicable: true → false` edit for free.
