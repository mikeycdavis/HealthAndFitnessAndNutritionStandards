# 0006 — Mermaid is the canonical diagram source

- **Status:** Accepted
- **Date:** 2026-08-09
- **Deciders:** project-owner

## Context

Architecture diagrams exist in two forms: a text source and a rendered image. Whichever one a person
edits becomes the real one, and if both are editable they diverge — usually silently, because a stale
rendered image looks exactly like a current one.

This repository additionally embeds diagrams into prose: `docs/architecture.md` contains a fenced
Mermaid block, and the adoption guide contains a decision flow. That creates a third copy, and copies
are what drift.

## Decision

The `.mmd` file is canonical. Everything else is derived.

- `docs/*.mmd` is the source of truth for every diagram.
- A diagram embedded in a Markdown document must appear as a ```` ```mermaid ```` fence whose content
  matches its `.mmd` file exactly, after whitespace normalisation.
- Any rendered `.svg` must carry a `<!-- mermaid-source-sha256: … -->` comment matching the digest of
  its normalised `.mmd`, and is a generated artifact — never hand-edited.
- An `.svg` with no sibling `.mmd` is a finding, not a diagram.

`scripts/diagrams.mjs` enforces all three by text comparison, with no Mermaid toolchain required. It
runs in CI. When no renderer is available, committing no `.svg` at all is permitted; what is not
permitted is a committed render that nothing checks.

The freshness check is mutation-tested: a test edits the canonical `.mmd` and asserts the check fails.
This is not ceremony. A comparable system shipped a freshness checker that compared only the first
line of each block and therefore reported clean on precisely the edit it existed to catch; it was
found by writing this test.

## Alternatives considered

**Commit only rendered images.** Rejected: an image cannot be reviewed in a diff, and the source is
then whatever a person had open in a diagram editor.

**Commit only `.mmd` and never embed.** Rejected: readers of `docs/architecture.md` and the adoption
guide should see the diagram in place. The embedded copy is a real requirement; the check exists
because it is a copy.

**Pair each `.mmd` to a specific host document.** Rejected. The check compares each `.mmd` against
every Mermaid block in the tree and requires a match somewhere, which allows one diagram to appear in
two documents without configuration.

## Consequences

- Adding a diagram means adding a `.mmd` and embedding it; adding a fence alone will pass (nothing
  requires every fence to have a source), but a `.mmd` without a matching embed will fail.
- `docs/architecture.md` is generated by a documentation pass and then checked by
  `npm run diagrams`; its diagram must never be edited in the Markdown.
- No `.svg` is committed in this release, and that absence is deliberate and declared here rather
  than left to inference.
